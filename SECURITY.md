# Security policy

## Supported versions

P2P Academy is in the `0.y.z` range. Security fixes are released in a new version, and older versions are not patched.

`p2p-academy update` installs the newest release on the default `stable` channel.

## Reporting a vulnerability

Do not open a public GitHub issue for a security vulnerability.

Report it privately through GitHub Security Advisories: [Report a vulnerability](https://github.com/thisonedev/p2p-academy/security/advisories/new).

Include as much detail as you can:

- The affected component and the app version. Settings > About shows it as "App version", with the commit in brackets.
- Your operating system.
- Steps to reproduce.
- What an attacker gains.
- A proof of concept or logs, if they are safe to share.
- A suggested fix, if you have one.

## Disclosure process

After receiving a report, maintainers aim to:

1. Respond within 5 working days.
2. Confirm whether the issue is valid and in scope.
3. Prepare and release a fix.
4. Coordinate the disclosure timing with the reporter, through a GitHub Security Advisory.

## Scope notes

Security issues in first-party code in this repository are in scope.

Reports that depend on a modified build, or on an issue already fixed on `master`, may be out of scope.
