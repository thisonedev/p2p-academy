In the previous lesson, we started an RPC server and gave it a discovery topic, a shared name that clients look up. Now we write the client, which picks two servers under that name and loads one model across their devices.

The SDK finds them with a function called `discoverRpcServers()`. It searches the topic for up to `timeoutMs` milliseconds and returns the candidates it found, each with a `url`, an `rdmaAvailable` flag and a list of `devices`.

The source example sorts the candidates and keeps the top two. Servers that offer RDMA come first, and ties are ordered by URL:

```ts
const selected = (await discoverRpcServers({ topic, timeoutMs: 5000 }))
  .sort((a, b) => Number(b.rdmaAvailable) - Number(a.rdmaAvailable) || a.url.localeCompare(b.url))
  .slice(0, 2);
if (selected.length !== 2) throw new Error("Two idle RPC servers are required");
```

In the academy, this sample stops at the check on the last line. Unless two machines on your network are serving on this topic, the search returns an empty list after about five seconds and the code throws `Two idle RPC servers are required`. The prefilled `catch` block prints the error, and `close()` still runs.

The next two steps both depend on the order of `selected`. Another function, `getRpcDeviceMap()`, assigns the aliases `RPC0`, `RPC1` and so on to the devices of the first server, then continues the count on the second:

```ts
const devices = getRpcDeviceMap(selected);
if (!devices.length) throw new Error("The selected servers expose no devices");
console.error(`▸ Using ${devices.length} devices across ${selected.length} servers`);
```

`loadModel()` then takes four RPC settings in `modelConfig`:

- `rpc-servers` lists the URLs of the selected servers, comma-separated and in the same sequence;
- `devices` lists the aliases to use;
- `split-mode` set to `"layer"` splits the model's layers across the devices;
- `tensor-split` holds one weight per device, and the example uses `1` for all of them, which makes the weights equal.

```ts
const modelId = await loadModel({
  modelSrc: LLAMA_3_2_1B_INST_Q4_0,
  modelConfig: {
    device: "gpu",
    "rpc-servers": selected.map((server) => server.url).join(","),
    devices: devices.map((device) => device.alias).join(","),
    "split-mode": "layer",
    "tensor-split": devices.map(() => "1").join(","),
  },
});
```

Only the machine that loads the model needs its file.

Once `loadModel()` resolves, running a completion takes no RPC settings. You write it as you would for a local model. The `finally` block unloads the model even when the stream fails, which the servers need before they are stopped:

```ts
try {
  const run = completion({
    modelId,
    history: [{ role: "user", content: "Explain distributed inference in one sentence." }],
    stream: true,
  });
  for await (const token of run.tokenStream) process.stdout.write(token);
  process.stdout.write("\n");
} finally {
  await unloadModel({ modelId });
}
```

> Note: A split is limited to 16 devices for now. Aliases start at `RPC0` again on every model load.
