So far, we've run every model on the devices of one machine. SDK 0.21 can also split a model across machines on a private network. That takes two roles: machines that serve their devices, and a client that loads the model across them.

This lesson covers the serving side. The SDK does it with a function called `startRpcServer()`. It starts a llama.cpp RPC server that the QVAC worker owns and returns the server's `serverId`, `url` and `rdmaCapable` flag.

By default the server binds to `127.0.0.1`, which only this machine can reach. To serve other machines, set `host` to this machine's private IPv4 address and set `allowNonLoopbackHost: true` as well.

`discoveryTopic` advertises the endpoint under a shared name that clients search for. The editor prefills both values as `host` and `topic`. Once you've replaced `host` with your own address, starting the server looks like this:

```ts
const server = await startRpcServer({
  host,
  allowNonLoopbackHost: true,
  discoveryTopic: topic,
});
```

A server has to stay up while clients use it, so the source example waits for the Enter key and then stops it:

```ts
const input = createInterface({ input: process.stdin, output: process.stderr });
try {
  console.error(`▸ Serving ${server.url}; RDMA capable: ${server.rdmaCapable}`);
  await input.question("▸ Press Enter to stop after clients unload their models.\n");
} finally {
  input.close();
  await stopRpcServer({ serverId: server.serverId });
}
```

`stopRpcServer()` withdraws the announcement and waits for the native server to stop. Clients have to unload any model that uses the endpoint before that.

> Note: Serving needs the `@qvac/ggml-rpc-server` package and a worker rebuilt with `"rpcServerProvider": "@qvac/sdk/ggml-rpc-server/provider"` in `qvac.config.json`. On the academy's standard worker, this sample ends with `RPC_SERVER_OPERATION_FAILED: startRpcServer: No RPC server provider registered`. The prefilled `catch` block prints that line without the stack trace, and `close()` still runs. The prebuilt packages use TCP. RDMA needs a client and worker rebuilt on Linux with RDMA enabled.

> Note: Native RPC traffic is unencrypted and unauthenticated, and a discovery topic doesn't authenticate peers. Run these servers on a trusted private network only.
