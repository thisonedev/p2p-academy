MOSS-Transcribe-Diarize turns a recording into a transcript with a speaker label and a time range on every segment.

The Q8_0 checkpoint is about 980 MB. We want to know whether it fits on this device before we download anything.

The SDK checks this with a function called `assessModelFit()`. Instead of the weights, it fetches a description of the model from the registry that is only tens of KB, and runs the engine's own fitter against it. For MOSS, the fitter also needs the length of the recording and the decoding options we'll use.

We pass both in `transcriptionWorkload`. This field is only for the fit check and doesn't change how the model loads later. It takes these settings:

- `audioSeconds` - the length of the longest recording we plan to transcribe, in seconds. It's required and must be positive.
- `hotwords`, `prompt` and `maxNewTokens` - the values we'd pass to `transcribe()`. `hotwords` and `prompt` are mutually exclusive.

Without a `transcriptionWorkload`, the MOSS fitter has nothing to project, and the verdict can stay `unknown`.

Each entry in `models` describes one model to check. It takes the same `modelType`, `modelSrc` and `modelConfig` we'd pass to `loadModel()`, with `transcriptionWorkload` added next to them.

The fitter reads `useGPU` and `maxThreads` from that `modelConfig`. We set them to the values we'll load the model with: no GPU and four CPU threads. The editor prefills `const audioSeconds = 300`, which covers a five-minute recording. The following code runs the fit check with those values:

```ts
const result = await assessModelFit({
  models: [
    {
      modelType: "moss-transcribe",
      modelSrc: MOSS_TRANSCRIBE_DIARIZE_Q8_0,
      modelConfig: { useGPU: false, maxThreads: 4 },
      transcriptionWorkload: { audioSeconds, maxNewTokens: 0 },
    },
  ],
});
console.log(JSON.stringify(result, null, 2));
```

`result.verdict` says whether all the models in the check fit together. Its value is one of `likely-fits`, `likely-too-large` or `unknown`. `result.models` repeats that field for each model and lists the `reasons` behind it.

> Note: A model's `evidence` says what its `verdict` is based on. `native-fit` means the engine's own fitter ran, and only this kind of evidence can confirm a fit. `computed-only` is a floor computed from catalog facts, so it can refuse a model but never confirm one.
