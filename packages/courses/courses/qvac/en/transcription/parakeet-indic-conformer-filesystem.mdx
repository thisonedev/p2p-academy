In the Parakeet CTC lesson, we transcribed English, the only language that model handles. For Indic languages such as Hindi and Tamil, the SDK has a second CTC model: Parakeet Indic Conformer.

One Indic Conformer checkpoint covers several languages. Its file stores a separate range of the vocabulary for each of them, and `modelConfig.language` selects which one the model decodes with.

The field takes a language id such as `hi` for Hindi or `ta` for Tamil. English CTC ignores it, but Indic Conformer requires it. The editor prefills `const language = "hi"` for you to pass in:

```ts
const modelId = await loadModel({
  modelSrc: PARAKEET_INDIC_CONFORMER_600M_Q8_0,
  modelType: "parakeet-transcription",
  modelConfig: { language },
});
console.log(`▸ Indic Conformer CTC model loaded with ID: ${modelId}`);
console.log(`▸ Language: ${language}`);
```

The language is set when the model loads, so `transcribe()` takes only the model ID and the path of a 16 kHz mono WAV file:

```ts
const text = await transcribe({
  modelId,
  audioChunk: "./examples/qvac/transcription/input/sample-hi.wav",
});
console.log(text);
```

The sample is about nine seconds of Hindi speech, and the output is a sentence in Devanagari script.

> Note: The id has to match the recording. Loaded with `ta`, the model writes the same Hindi file out in Tamil script, because decoding is limited to the Tamil part of the vocabulary. With no `language` at all, the model still loads, and `transcribe()` resolves to the string `[Inference error]` without throwing an error.
