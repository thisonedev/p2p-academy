In this lesson, we're going to transcribe a recording with a speaker label and time range on every segment, using a model called MOSS-Transcribe-Diarize.

Earlier in the chapter, we needed two models for this. Sortformer found the speaker turns, then TDT transcribed each slice. MOSS does both in one batch pass.

MOSS loads with its own model type, `moss-transcribe`. The Q8_0 checkpoint is about 980 MB. The registry also has F16 and Q5_0 variants. `modelConfig` takes two settings:

- `maxThreads` - sets the number of CPU threads, and `0` lets the engine choose.
- `useGPU` - turns on the linked GPU backend, including Metal. It defaults to `false`.

We give MOSS four CPU threads and turn off the GPU:

```ts
const modelId = await loadModel({
  modelType: "moss-transcribe",
  modelSrc: MOSS_TRANSCRIBE_DIARIZE_Q8_0,
  modelConfig: {
    maxThreads: 4,
    useGPU: false,
  },
});
console.log(`▸ MOSS model loaded with ID: ${modelId}`);
```

Besides the model ID, `transcribe()` takes the path of a 16 kHz mono WAV file and two more options:

- `metadata: true` - switches the result from one string to an array of segments.
- `maxNewTokens` - caps the number of tokens MOSS generates, and `0` keeps the model's default limit.

We pass both options as follows:

```ts
const segments = await transcribe({
  modelId,
  audioChunk: audioFilePath,
  metadata: true,
  maxNewTokens: 0,
});
```

Each segment has its text and a time range in `startMs` and `endMs`. It also has two speaker fields: a `speaker` label such as `S01` and a zero-based `speakerId`.

Both speaker fields are optional in the segment type, so the loop falls back from the label to the number, then to a placeholder:

```ts
for (const segment of segments) {
  const start = (segment.startMs / 1000).toFixed(2);
  const end = (segment.endMs / 1000).toFixed(2);
  const speaker =
    segment.speaker ??
    (segment.speakerId !== undefined ? `Speaker ${segment.speakerId}` : "Unknown speaker");
  console.log(`[${start}s → ${end}s] ${speaker}: ${segment.text.trim()}`);
}
```

> Note: MOSS only transcribes whole recordings. Duplex streaming with `transcribeStream()` and configuration reload are not available for it.

> Note: You can pass names and domain terms for a recording as `hotwords`, up to 64 non-empty entries of at most 64 UTF-8 bytes each. A custom instruction is the `prompt` option instead. `hotwords` and `prompt` are mutually exclusive. Passing both makes `transcribe()` reject with an error.
