Before you download a model, you can check whether it fits in memory. `assessModelFit` runs that check without fetching the weights.

For each candidate, it fetches a registry description of tens of KB and runs the engine's own fitter against it. The result is `likely-fits`, `likely-too-large`, or `unknown`.

If the fitter can't run, the SDK works out a minimum from the file size instead. For llama.cpp engines, that minimum includes the KV cache.

The SDK compares that number with the memory budget only when the model runs from system RAM, as on a CPU-only desktop or an integrated GPU. On a desktop with a discrete GPU, the result is `unknown`.

If the minimum is over the budget, the result is `likely-too-large`. Under the budget, the SDK can't confirm a fit and returns `unknown`. The minimum leaves out memory the model only uses once it's loaded, such as engine overhead and compute buffers.

`assessModelFit` takes two more inputs that affect the result:

- `execution: 'sequential'` counts every candidate as resident in memory at the same time, as when you load them one after another and keep them all.
- `policy: 'interactive-v1'` withholds a slice of whatever memory is free right now, so the result leaves headroom for the rest of the system. On desktop, that reserve is 20% of free memory, capped at 2 GiB.

Each entry in `models` has the same fields as the options of `loadModel()`. In this lesson, that's `modelSrc` and a `modelConfig` with the `ctx_size` to assess. Pass both candidates in one array to check whether they fit side by side:

```ts
const result = await assessModelFit({
  models: [
    { modelSrc: QWEN3_600M_INST_Q4, modelConfig: { ctx_size: 8192 } },
    { modelSrc: QWEN3_8_27B_MULTIMODAL_UD_Q8_K_XL, modelConfig: { ctx_size: 8192 } },
  ],
  execution: "sequential",
  policy: "interactive-v1",
});

const gib = (n: number) => (n / 1024 ** 3).toFixed(2);
if (result.budget) {
  console.log(`▸ Budget: ${gib(result.budget.availableAfterReserveBytes)} GiB free`);
}

for (const model of result.models) {
  console.log(`▸ ${model.name}: ${model.verdict}`);
}

console.log("▸ Combined verdict:", result.verdict);
```

If the larger model doesn't fit on your machine, `QWEN3_600M_INST_Q4` still gets `likely-fits`. The combined `result.verdict` adds the larger model on top, so it comes out `likely-too-large`.

> Note: `assessModelFit` is advisory only. It never blocks `loadModel`, reserves memory, or picks a model for us. We still decide what to do with a `likely-too-large` or `unknown` result.
