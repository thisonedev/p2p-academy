`assessModelFit()` estimated the fit before anything was downloaded. The SDK also runs a second check on its own, right before it loads a model for completions or embeddings.

This one reads the model file already on disk and projects whether it fits in device memory with the exact settings you passed to `loadModel()`.

The verdict is `fit`, `does-not-fit` or `unknown`. Unlike `likely-fits`, these values don't hedge, because the check measured this file against this device. They never stop `loadModel()` either.

A `does-not-fit` verdict only logs a warning, and loading continues unchanged. `unknown` means the check had no evidence, for example because it timed out or doesn't support that kind of model.

`loadModel()` still resolves to the `modelId` alone. The SDK writes the verdict to a log stream, which you read with `loggingStream()` and the `SDK_LOG_ID` constant. Start watching the stream first, so the watcher is already running when the verdict line appears:

```ts
void (async () => {
  for await (const log of loggingStream({ id: SDK_LOG_ID })) {
    if (log.message.includes("[advisory-fit:")) {
      console.log(`▸ Fit check: ${log.message}`);
    }
  }
})().catch(() => {});
```

Other SDK messages share the stream, so the `includes()` filter keeps only the fit verdicts.

With the watcher running, load the model from the first lesson:

```ts
const modelId = await loadModel({ modelSrc: LLAMA_3_2_1B_INST_Q4_0 });
console.log(`▸ Model loaded: ${modelId}`);
```

The check can delay `loadModel()` by up to 30 seconds before it gives up with `unknown`. The open log stream also keeps the process alive, so the starting file ends with `process.exit(0)` after the unload.

> Note: Setting the `QVAC_ADVISORY_MODEL_FIT` environment variable to `0` turns the check off, so the SDK logs no verdict.
