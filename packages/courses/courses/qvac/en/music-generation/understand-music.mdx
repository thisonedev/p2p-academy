Every lesson in this chapter so far has produced audio. In this lesson, we're going to give ACE-Step a finished track and read a description of it back.

The SDK does this with a function called `audioUnderstand()`. It takes a recording and returns a caption with the tempo, key and time signature of the clip.

The engine first encodes the recording and recovers five semantic codes for each second of audio. Then the LM samples the description, and `seed` fixes the randomness.

The model setup matches the earlier lessons, so start by passing the loop to `audioUnderstand()` and draining its progress:

```ts
const run = audioUnderstand({
  modelId,
  sourceAudio: sourcePath,
  seed: 11,
});

for await (const progress of run.progressStream) {
  console.log(`▸ ${progress.stage}: ${progress.step}/${progress.total}`);
}
```

Instead of `audio`, the result holds a `description` promise. Once it resolves, log the fields you need:

```ts
const description = await run.description;
console.log(`▸ Caption: ${description.caption}`);
console.log(`▸ ${description.bpm} BPM, ${description.keyscale}, ${description.timesignature}`);
console.log(`▸ Vocal language: ${description.vocalLanguage}`);
console.log(`▸ Estimated duration: ${description.duration.toFixed(1)} s`);
console.log(`▸ Recovered ${description.audioCodes.length} semantic codes`);
```

The LM fills in `vocalLanguage` on its own. If you already know the language of a vocal track, pass it to `audioUnderstand()` as `vocalLanguage`, such as `"es"`. The result then reports your value.

You can pass `audioCodes` to `audioGen()` as its `audioCodes` option to re-synthesize the clip without running the LM again.

> Note: `duration` is the LM's estimate. The recovered codes set the true length, so dividing `audioCodes.length` by five gives the real duration in seconds.
