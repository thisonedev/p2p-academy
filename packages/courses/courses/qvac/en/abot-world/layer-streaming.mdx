The walk from the previous lesson holds its weights in video memory (VRAM), which is the default. At 832x480, that takes at least 20 GB, which in practice means a 24 GB card.

The main model is `ABOT_WORLD_0_5B_Q8_0`, the one passed as `modelSrc`. It generates the walk, while the other three files encode the prompt and convert frames. For a card that cannot hold this model, the SDK has four more `world` fields, which lower VRAM use and make the walk slower:

- `paramsBackend` is where weights are held. We set it to `"diffusion=cpu"`, which puts the model's weights in system RAM;
- `maxVram` is the VRAM budget in GiB for running it;
- `streamLayers` is the option that keeps its first segments inside that budget and transfers the rest from system RAM;
- `verbosity` is the engine log level from `0` for errors to `3` for debug.

`streamLayers` needs those weights in system RAM, GPU execution and a nonzero `maxVram`. If any of the three is missing, it does nothing.

Add all four fields to the `world` object in `loadModel()` and leave the fields already in it as they are. The rest of the file doesn't change:

```ts
const modelId = await loadModel({
  modelSrc: ABOT_WORLD_0_5B_Q8_0,
  modelType: "sdcpp-generation",
  modelConfig: {
    mode: "world",
    taehvModelSrc: ABOT_WORLD_0_5B_LF_TAEHV_VAE,
    t5XxlModelSrc: UMT5_XXL_ENC_Q8_0,
    vaeModelSrc: ABOT_WORLD_0_5B_LF_WAN_VAE,
    world: {
      seed: 42,
      kvCache: true,
      frameJpegQuality: 85,
      paramsBackend: "diffusion=cpu",
      maxVram: 2,
      streamLayers: true,
      verbosity: 3,
    },
  },
});
```

The 2 GiB set with `maxVram` covers the main model only. The attention history, the streaming decoder and the scene allocate on top of it, so leave room for them. The minimum VRAM for a streamed walk at 832x480 has not been measured yet.

> Note: these fields only work nested under `world`. The flat `params_backend`, `max_vram`, `stream_layers` and `verbosity` keys that image and video generation accept don't reach a walk session. If you pass one in world mode, `loadModel` fails with an error that names its `world.*` equivalent.
