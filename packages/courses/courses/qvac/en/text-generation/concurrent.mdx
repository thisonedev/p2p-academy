In the previous lessons we've been running the `completion()` function one at a time. Now let's see what happens when we fire two simultaneously.

Two completions on the same model can't truly run at once, because a loaded model maps to one native context, with a single KV-cache and a single decode loop. The SDK uses a per-`(kind, modelId)` FIFO admission queue, so the second completion waits its turn instead of being rejected with `RequestRejectedByPolicyError`.

Fire both `completion()` invocations in the same tick, with no `await` between them. The two back-to-back runs look as follows:

```ts
const r1 = completion({ modelId, history, stream: false, captureThinking: true });
const r2 = completion({ modelId, history, stream: false, captureThinking: true });
```

Next, we'd use the canonical pattern to await the results. `Promise.all` waits on both and resolves to:

```ts
const [text1, text2] = await Promise.all([r1.text, r2.text]);
console.log(`▸ req-A: ${text1}`);
console.log(`▸ req-B: ${text2}`);
console.log(`▸ Both completed.`);
```

Both `completion()` invocations fire synchronously, so both end up "in flight" against the SDK's queue. `Promise.all` then waits for them. On the same model, the queue runs them in order. On different models, the per-model key means they run in parallel.

> Note: if you `await` the first `completion()` before firing the second, there's never a moment when both need the same native context at once, so the queue is bypassed. Fire both first, await together.
