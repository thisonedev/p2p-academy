In this lesson, we're going to run four completions through one shared decode loop, using a model called Llama 3.2 1B Instruct.

Instead of bundling prompts into one `batchCompletion()` run, you can invoke `completion()` several times on the same model.

By default, a model handles one request at a time. If you load it with `parallel` set to 2 or more, the add-on decodes up to that many completions in one shared loop, taking one token from each on every step. They finish in roughly the time of the slowest one. Anything beyond that limit waits in a queue.

The context window is split evenly across those completions. With `ctx_size: 4096` and `parallel: 4`, a completion gets about 1024 tokens:

```ts
const modelId = await loadModel({
  modelSrc: LLAMA_3_2_1B_INST_Q4_0,
  modelType: "llm",
  modelConfig: { ctx_size: 4096, parallel: 4 },
});
```

Our four prompts ask for one-word replies:

```ts
const PROMPTS = [
  { id: "cherry", ask: "Reply with only the word CHERRY." },
  { id: "banana", ask: "Reply with only the word BANANA." },
  { id: "grape", ask: "Reply with only the word GRAPE." },
  { id: "lemon", ask: "Reply with only the word LEMON." },
];
```

We start all four before awaiting any. That way the SDK can admit them in one go instead of one after another:

```ts
const started = Date.now();
const runs = PROMPTS.map(({ ask }) =>
  completion({
    modelId,
    history: [{ role: "user", content: ask }],
    generationParams: { temp: 0, seed: 42, predict: 16 },
    stream: true,
  }),
);
```

Every `completion()` is independent. Its `final` promise has its own `contentText` and `stats`, including tokens per second. We wait for all four and print the replies:

```ts
const outputs = await Promise.all(
  runs.map(async (run, i) => {
    const final = await run.final;
    return {
      id: PROMPTS[i]!.id,
      text: final.contentText.replace(/\s+/g, " ").trim(),
      stats: final.stats,
    };
  }),
);
const elapsed = Date.now() - started;

for (const { id, text, stats } of outputs) {
  const tps = stats?.tokensPerSecond?.toFixed(1) ?? "n/a";
  console.log(`  ▸ ${id}: "${text}"  (own ${tps} tok/s)`);
}
```

`stats` also has a model-level field, `avgConcurrentSeq`, which shows how busy the shared backend was. A value above 1 means the add-on decoded more than one sequence per step:

```ts
const peakConcurrent = Math.max(...outputs.map((o) => o.stats?.avgConcurrentSeq ?? 0));
console.log(
  `\n▸ All 4 finished in ${elapsed} ms; engine avg concurrent sequences: ${peakConcurrent.toFixed(1)} (> 1 = decoded together).`,
);
```

A `completion()` result includes a `requestId`. Passing it to `cancel()` stops that completion alone, while the others keep decoding. We test this with two long stories, one about an otter and one about a melon:

```ts
const doomed = completion({
  modelId,
  history: [{ role: "user", content: "Write a long story about an otter." }],
  generationParams: { temp: 0, seed: 1, predict: 256 },
  stream: true,
});
const survivor = completion({
  modelId,
  history: [{ role: "user", content: "Write a long story about a melon." }],
  generationParams: { temp: 0, seed: 42, predict: 256 },
  stream: true,
});
```

First, we wait for an event from both, so the otter story is already decoding when we stop it:

```ts
const survivorTokens = survivor.events[Symbol.asyncIterator]();
await Promise.all([doomed.events[Symbol.asyncIterator]().next(), survivorTokens.next()]);

await cancel({ requestId: doomed.requestId });
```

`doomed.final` then rejects with an `InferenceCancelledError`. Meanwhile, the melon story keeps streaming, and we count how many events it emits from then on:

```ts
let doomedCancelled = false;
try {
  await doomed.final;
} catch (err) {
  doomedCancelled = err instanceof InferenceCancelledError;
}

let tokensAfterCancel = 0;
for (let next = await survivorTokens.next(); !next.done; next = await survivorTokens.next()) {
  tokensAfterCancel++;
}
console.log(`  ▸ cancelled run -> ${doomedCancelled ? "cancelled" : "NOT cancelled"}`);
console.log(`  ▸ peer kept decoding -> +${tokensAfterCancel} tokens after the cancel ack`);
```

> Note: if you await one `completion()` before starting the next, they run in sequence, even with a higher `parallel`.
