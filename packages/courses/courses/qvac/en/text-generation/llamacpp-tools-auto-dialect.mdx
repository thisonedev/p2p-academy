In this lesson, we're going to call tools without naming the tool-call format, using a model called Qwen3.5 0.8B.

The SDK matches the model's name and file name against known model families and uses the parser of the family it finds.

Turn on tool calling with `tools: true` in `modelConfig`:

```ts
const modelId = await loadModel({
  modelSrc,
  modelType: "llamacpp-completion",
  modelConfig: { ctx_size: 4096, tools: true },
});
```

The SDK picks the dialect when a `completion()` run includes tools. The supported families are Qwen3.5/3.6/3.8, Gemma4, GPT-OSS, DeepSeek V3.2/V4, and LFM. Any other model gets the `hermes` dialect. To pin a dialect yourself, pass `toolDialect` to `completion()`.

The model needs a contract before it can request a tool. Define each entry with a name, a description, and a Zod object for its parameters:

```ts
const weatherSchema = z.object({
  city: z.string().describe("City name"),
  country: z.string().describe("Country code").optional(),
});

const horoscopeSchema = z.object({
  sign: z.string().describe("An astrological sign like Taurus or Aquarius"),
});

const tools: ToolInput[] = [
  {
    name: "get_weather",
    description: "Get current weather for a city",
    parameters: weatherSchema,
  },
  {
    name: "get_horoscope",
    description: "Get today's horoscope for an astrological sign",
    parameters: horoscopeSchema,
  },
];
```

With the contract in place, pass `tools` beside the conversation history. The completion now exposes token and tool-call streams separately:

```ts
const result = completion({ modelId, history, stream: true, tools });
```

Those streams represent one response, so drain both before reading the final calls. `Promise.all` keeps neither stream waiting on the other. The parallel drain looks like so:

```ts
const tokensTask = (async () => {
  for await (const token of result.tokenStream) {
    process.stdout.write(token);
  }
})();

const toolsTask = (async () => {
  for await (const evt of result.toolCallStream) {
    if (evt.type === "toolCall") {
      console.log(`\n▸ ${evt.call.name}(${JSON.stringify(evt.call.arguments)})`);
    }
  }
})();

await Promise.all([tokensTask, toolsTask]);
```

Each `toolCall` event has `evt.call.name` and `evt.call.arguments`. The arguments are already parsed into a JS object; pass them straight to the matching function.

After both streams finish, read `result.toolCalls` for the full list of tool calls and print the summary:

```ts
const toolCalls: ToolCall[] = await result.toolCalls;

console.log("\n\n▸ Final tool calls:");
if (toolCalls.length > 0) {
  for (const call of toolCalls) {
    console.log(`▸ ${call.name}(${JSON.stringify(call.arguments)})`);
  }
} else {
  console.log("▸ (none)");
}

await unloadModel({ modelId, clearStorage: false });
```

> Note: when you bring your own model with a known tool-call dialect that its file name doesn't reveal, pass that dialect as `toolDialect` in `completion()`, for example `toolDialect: "gemma4"`.
