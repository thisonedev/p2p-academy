In this lesson, we're going to split one model across two GPUs, using a model called Llama 3.2 1B Instruct.

A completion model runs on a single GPU by default. On a machine with two or more, `modelConfig` has three settings that spread it across them:

- `split-mode` - how the model is split: `'none'` (the default, one GPU), `'layer'`, which splits the layers and the KV cache across the GPUs, or `'tensor'`, an experimental tensor parallelism that needs flash attention;
- `tensor-split` - the proportions of the layers each GPU gets, such as `'1,1'` for an equal split or `'3,1'` for 75% and 25%;
- `main-gpu` - the GPU to use on a multi-GPU system, as a device index or `'integrated'`/`'dedicated'`.

To give each of two GPUs an equal share of the layers, we set `'split-mode': 'layer'` and `'tensor-split': '1,1'`:

```ts
const modelId = await loadModel({
  modelSrc: LLAMA_3_2_1B_INST_Q4_0,
  modelType: "llamacpp-completion",
  modelConfig: {
    "split-mode": "layer",
    "tensor-split": "1,1",
    "main-gpu": 0,
    ctx_size: 4096,
    gpu_layers: 99,
    verbosity: VERBOSITY.ERROR,
  },
});
```

The code also sets `gpu_layers: 99`, which pins the number of layers offloaded to the GPUs and turns off the SDK's automatic fit to free device memory.

`completion()` takes no split settings of its own. With the model spread across both GPUs, we stream the answer to a question about parallelism and log the stats at the end:

```ts
const result = completion({ modelId, history, stream: true });
for await (const token of result.tokenStream) {
  process.stdout.write(token);
}
const stats = await result.stats;
console.log("\n\n▸ Stats:", stats);
```

> Note: `tensor-split` needs one value per GPU. On a machine with a single GPU, `'1,1'` makes `loadModel()` fail with a `MODEL_LOAD_FAILED` error, which says that `tensor-split` has 2 values for 1 GPU device.
