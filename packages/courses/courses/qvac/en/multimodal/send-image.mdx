Now that we have a multimodal model in memory, it's time to give it an image.

The multimodal model takes a prompt that includes an image as well as text. We tell it what to look at by attaching an image file to a user message. `attachments[].path` is the only thing it needs, a string path to a real file on disk.

We don't swap the chat structure. We add `attachments` to the existing `history` message we already use for text completions.

The SDK reads the bytes, then the projector encodes them before the message reaches the LLM. We add one extra field to the existing history entry:

```ts
attachments: [{ path: "./examples/qvac/multimodal/input/cat.png" }],
```

Running `completion()` kicks off multimodal completion. We just add an `attachments` array to the user message:

```ts
const result = completion({ modelId: multimodalId, history, stream: true });
```

We also print a trailing `\n` once the stream ends:

```ts
for await (const token of result.tokenStream) {
  process.stdout.write(token);
}
process.stdout.write("\n");
```

The path is relative to where we run the script from, or absolute if we prefer. We drop any local `.jpg` or `.png` at the path we pass in.

> Note: the multimodal model needs the projector loaded (from the previous lesson) to interpret the image. If `projectionModelSrc` was missing, the model would silently ignore the attachment and respond as if no image was attached.
